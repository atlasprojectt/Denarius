## 1. Principles

- One question drives everything: **"am I in control of AI spend?"** answered in ≤10s.
- **Verdict-first**: the screen states the conclusion (one deterministic sentence + color); details justify it below.
- Money headlines; tokens are drill-down. Semaphore colors (green/amber/red) are **reserved for budget status** — deltas and everything else stay neutral.
- Honesty in the chrome: "as of <date>" stamps, stale banners, "uncosted", disclosed FX. Never a number the system can't defend.
- Control, not surveillance: per-person data only in context ("contributors to this spike"), names Admin-only.

## 3. Home component contracts

1. **Onboarding checklist** (dismissible, 4 steps, budget step pushed) — only until complete.
2. **Stale-data banner** — only when a connector hasn't synced >1 day.
3. **Verdict line** — always present; green/amber/red; one SHORT deterministic sentence (2026-07-17 de-noise: red names the breached team and its **own** overrun — "Engenharia ultrapassou o orçamento em 19%."; amber/green carry only the projected delta, no close date). On a team-red verdict the engine exposes `verdict.teamId` and the line renders an optional **"Ver time →"** contextual action (`VerdictLine`'s `action` prop, neutral `tertiary` button at rest and hover) to `/times?focus=<id>`. The UI never re-derives the breached team — it must match the sentence's tie-break.
4. **Hero** (de-noised 2026-07-17, founder-directed): card title **"Gasto do mês"** (regular L2 card title, no longer a muted description) over the org spend big number (the product's identity — never demote it to a KPI tile; it now dominates by SUBTRACTION, not enlargement) with a **week-over-week delta pill** under it (rounded neutral pill, `▲ +12% vs semana anterior` — reported `cost_daily` through the digest's own `weekOverWeek`, so screen and email never disagree; NEUTRAL per P5, hidden when the previous week has no spend **or |Δ| < 0,5%** — a "0,0%" chip is noise); then **ONE pacing bar** (`PacingBar`, replacing the old `PacingPair` two-bar stack): the `h-4` `TICKS_BOLD` spend bar uses medium brand accent while realized org spend is within budget and turns red only after a real breach (`pctSpent > 1`), with % spent right-aligned above, neutral projection ghost, budget marker — and the month's elapsed time folded into a **"hoje" tick under the same scale** labeled `hoje · dia N de M` (label hugs the tick mid-bar, pins to the edge near day 1/31). The spend-vs-time pairing survives as marker position, not a second bar; `barGeometry` unchanged. Below the bar, a **single KPI** — "Projeção de fechamento" (emphasis weight, neutral ink) — the projected margin's home is now the verdict sentence, and the old projected-margin KPI + callout sentence were removed as duplicates. The unconverted-USD honesty footer stays (invariant #4, never a tooltip). **Read-only** since 2026-07-09 — no inline pencil. The day-of-month meta line left the page's top-right corner: the "hoje" marker is its one canonical home (only the quiet `dados de <stamp>` freshness stamp remains up there, per principle #3).
5. **Orçamento dos times (table)**: ONE stable table for every budgeted team, at-risk first (cockpit ordering). Columns: Time · Situação (status pill) · Gasto · Orçamento · Consumo (bar + %) · Projeção · chevron. The permanent warning sentence under at-risk names was **removed in the 2026-07-17 de-noise** — the pill IS the resting signal; its full reason (`warnBreach`/`warnProjected`/`warnThreshold`) now lives in a **tooltip on the pill** (`TeamStatus`, click-stopped so a tap on the chip reveals the reason instead of navigating). Row dividers softened to `border-border/60` (less spreadsheet-like). No expanding rows, no collapsed "Sob controle" group, no inline actions — the whole row links to `/times?focus=<id>` (the team's diagnosis card, expanded and scrolled to — Fase 1, 2026-07-16); a single "Gerenciar orçamentos" action heads to `/ajustes/orcamentos`. (Replaced the rich `TeamRow` + `UnderControl` collapse.) Since Fase 1 the table is **Home-only** (`components/domain/team-budget-table.tsx` — Times replaced it with diagnosis cards); Fase 2 will replace it on Home with the triage rows. Variant switching is **container-query based** (`@container` on the CardContent; compact card list below `@2xl` of the card, table above, Consumo bar column from `@3xl`); Home forces `variant="table"` so the half-width cockpit cell never changes design as the window resizes.
6. **Observações**: calm feed (no red, no urgency), includes unattributed nudge.
7. **Dashboard panels** (titles standardized + de-noised 2026-07-17): **"Gasto por fonte"** (provider/seat composition as **ranked horizontal tick bars** with provider brand marks — the donut was retired 2026-07-14; neutral foreground-ramp colors, share-cut fills, beside the hero. The "Total convertido" block was **removed** — the total is the hero's; the entry value is now primary-datum weight. The permanent explainer moved into a title-side **`InfoTip`** (the reconciliation equation lives there too). The CardFooter reconciliation line is now the **compact clickable notice** `"<amount> sem atribuição — Corrigir →"` — hidden at cents-zero, FX-missing still fully disclosed, linking to Atribuição) and **"Evolução do mês"** (an **EvilCharts area chart**, bottom-left grid cell, current spend + linear projection; title-side `InfoTip`; a labeled **"hoje · <valor>" dot** marks the current point, and on a projected breach a **neutral-ink** `"+<delta> vs orçamento"` annotation states how far the run-rate lands over budget — a delta, not a status, principle #5). Team distribution stays in the teams table, not as a second composition panel. The 2x2 grid uses **a content-sized top row and a flexible bottom row** (`xl:grid-rows-[auto_minmax(0,1fr)]`, compact 16px gaps — proportion pass 2026-07-14): the dense hero sets row 1's height and the composition card distributes only its entry list over that same height (`justify-evenly`, not centered). Row 2 absorbs every leftover viewport pixel and the pace plot grows with it (`h-full`, `min-h-[220px]`) — extra height becomes chart, not voids inside the top cards. On a 1920-wide desktop the cockpit fills the viewport without page scroll; narrower desktops (~1440) scroll only as far as the teams table needs.

**States that must exist:** cold-start (no data/budget → CTA hero, never empty), collecting-pace (before day 5), **all-clear** ("✓ Tudo sob controle · próximo digest sexta"), stale-data, breached. Since 2026-07-15 the **all-clear and stale-data states render in the sidebar** (see §5, `SidebarNotice`), not in the Home column — they are chrome, standing on every route, and a "nothing to do" card should not push the cockpit grid down. Home keeps the verdict line as its affirmative answer.

**#19 implementation:** the page is a Server Component reading `getHomeData()` (`lib/home/queries.ts`), which gathers raw spend parts under RLS and hands them to the pure engine `buildCockpit()` (`lib/engine/cockpit.ts`) — all arithmetic, the seats+API frozen-FX combine, the verdict, the per-team findings, and the needs-attention/under-control partition live there, not in the components (architecture §9). The org spend headline uses provider-**reported** cost (`cost_daily`, the USD source of truth); per-team spend uses **derived** cost (`usage_daily`, the only grain with team attribution). Provider composition converts each provider's reported USD at the org frozen FX and adds the seat slice; when FX is missing the API cost is dropped from the list and disclosed as unconverted (never mixed currencies). New cross-screen domain components: `VerdictLine`, `StatusPill`, `BudgetBar` (fill + dashed run-rate ghost + budget marker, geometry in the pure `lib/bars.ts`).

## 5. Interaction patterns

### Button system (2026-07-17)

All product actions use `components/ui/button.tsx`, backed by Base UI + CVA. Do not recreate button chrome at call sites: `className` is for positioning or a narrowly scoped composition adjustment only. The internal reference page is `/ajustes/botoes`.

| Variant | Use | Resting treatment |
|---|---|---|
| `primary` | The one main action in a screen, form or dialog | Brand-orange fill, high-contrast ink |
| `secondary` | Important global or supporting action | Neutral fill + subtle border |
| `tertiary` | Contextual card, alert or row action | Near-transparent neutral surface; hover lifts the neutral surface/border while only its icon or chevron may use `accent-light` |
| `ghost` | Navigation, menus and icon-only controls | No resting surface or border |
| `destructive` | Irreversible delete/remove/revoke only | Destructive red treatment |
| `outline` | Alternative action in a form/dialog | Transparent neutral surface + border |

Sizes are fixed: `sm` 28px (14px icons), `default` 36px (16px icons), `lg` 40px, `icon` 36×36px and `icon-sm` 28×28px. Primary and secondary actions use the 14px `lg` radius; compact contextual actions opt into the `pill` shape; icon-only sizes are circular. Right-side navigation uses the same Remix `RiArrowRightSLine` chevron and inherited size everywhere. `loading` + `loadingText` keeps the control width stable, sets `aria-busy`, disables repeat interaction and renders the shared spinner. Icon-only buttons require `aria-label`; native `type` remains explicit at submit/reset call sites.

### Button motion (2026-07-18)

Button motion is centralized in `Button` and is driven by action intent, never by control size. The shared tokens are `--motion-duration-fast: 120ms`, `--motion-duration-standard: 160ms`, `--motion-duration-max: 180ms`, `--motion-ease-standard: cubic-bezier(0.22,1,0.36,1)`, `--motion-icon-shift: 3px` and `--motion-button-lift: 1px`.

| Intent | Hover | Active | Focus |
|---|---|---|---|
| `primary` | Background gains contrast and the container rises at most 1px | Returns through the origin and presses down at most 1px | Stable accent ring; no movement |
| `secondary` / `outline` | Neutral surface, border and ink gain restrained contrast | Surface darkens slightly; container stays fixed | Stable accent ring; no movement |
| `tertiary` / contextual | 120ms neutral surface/border transition; only a semantic end chevron may gain accent-light and move | Directional icon falls back to a 1px displacement; container stays fixed | Stable accent ring; no movement |
| `destructive` | Controlled red surface/border contrast only | Surface pressure only; no shake, pulse or glow | Stable destructive ring; no movement |
| icon-only | Surface/contrast by default; movement only when the icon's meaning requires it | Semantic feedback only | Stable ring; no movement |

Directional controls opt into `motion="forward"` or `motion="backward"`, and mark only the semantic arrow with `data-icon="inline-end"` or `data-icon="inline-start"`. Disclosure controls use `motion="disclosure"` plus `data-icon="disclosure"`, rotating only that chevron while `aria-expanded=true`. This keeps labels and unrelated icons still. Hover displacement runs only on devices that actually support hover; touch receives the short active response. Loading keeps the original content in layout at zero opacity, centers an overlaid spinner, sets `disabled` + `aria-busy` and suppresses hover/active transforms. Disabled controls likewise have no movement or hover interaction. Under `prefers-reduced-motion`, elevation, directional displacement, disclosure rotation and spinner rotation are removed; only the short color/background/opacity transitions remain.

The internal `/ajustes/botoes` reference renders hover, active, keyboard focus, loading and disabled examples for direct inspection. This intent-based policy supersedes any earlier generic press-motion wording.

- **Motion layer** (updated 2026-07-15): Base UI remains the primitive base. Controls use the preset's restrained one-pixel press response rather than hover lift or icon scaling; popovers/dialogs retain short soft entrances and respect `prefers-reduced-motion`. - **Route entrance** (2026-07-18): `PageTransition` wraps the `(app)` route content through `template.tsx`, below the persistent sidebar and topbar. - **Sidebar label choreography**: labels, group headings, and the wordmark combine their crossfade with a restrained 4px horizontal drift. Icons do not scale or transform; their invariant slot and monotonic path remain the geometric anchor.

**Motion policy** (updated 2026-07-15): shared controls follow the preset's restrained press feedback, while chart/bar construction is controlled app-wide by the `RevealController` + CSS keyframes so it restarts on navigation and viewport entry (Home cockpit and the Explorar team drill-down; the Explorar list and the big money numbers stay static). Keep transitions short and executive-calm. Never use hover lift, icon zoom or a sliding menu hover indicator; menus/sidebar remain simple color/focus interactions. **Base UI dropdown gotchas** (found 2026-07-09 fixing the sidebar profile menu): (1) `DropdownMenuLabel` wraps Base UI `Menu.GroupLabel`, which **throws "MenuGroupContext is missing" outside a `<Menu.Group>`** — for a plain identity header inside the menu, use a styled `<div>`, not `DropdownMenuLabel`. (2) Composing `DropdownMenuTrigger asChild` through another render-prop component (e.g. `SidebarMenuButton`, itself a `TooltipTrigger`) **swallows the trigger's open/close handlers and the menu never opens** — use a plain `DropdownMenuTrigger` (it renders its own native button) styled to match, with an `aria-label` for the collapsed rail.

**Button icon-size gotcha** (found 2026-07-09 — the header sidebar toggle rendered a 12px speck): the `Button` base carries `[&_svg:not([class*='size-'])]:size-3`, whose `:not([class*=…])` gives it **higher specificity than any parent `[&_svg]:size-*` override** — such overrides silently lose. The intended escape hatch is a `size-*` class **on the svg itself** (that's what the `:not()` guard checks). Any icon inside a `Button` that should not be 12px must carry its own size class (e.g. `SidebarTrigger` now renders `<RiSidebarFoldLine className="size-5" />`).

**`asChild`-from-a-Server-Component gotcha** (found 2026-07-15 — the "Definir orçamentos" button on `/times` rendered as an empty stub and the hydration mismatch garbled the card): an element passed as `asChild` children **from a Server Component** arrives at the client primitive as a `react.lazy` element (react#32392). Base UI's `evaluateRenderProp` merges the primitive's props with `render.props` *before* unwrapping the lazy element — `render.props` is `undefined` at that point — so any explicit `children` key on the primitive, **even `null`**, wins in `cloneElement` and wipes the render element's label out of the SSR HTML. Client-component call sites are unaffected (their elements are local, `render.props.children` survives), which is why the bug hides: identical JSX works on one screen and breaks on another. Fix pattern (applied to `Button`): when `render` is set, omit the `children` key entirely (`{...(render ? {} : { children })}`), never pass `{render ? null : children}` as a JSX child. `dropdown-menu.tsx`/`sidebar.tsx` still carry the generated null-children pattern but are only composed from client components today — apply the same fix there if a server component ever feeds them an `asChild` element.

**`Item` primitive gotcha** (found 2026-07-09 — `/configuracoes` rendered a blank card): `Item` is built on Base UI `useRender`, which only renders children it receives via `props`. The generated component destructured `children` out and never forwarded it, so a plain `<Item>…</Item>` (no `asChild`) rendered an empty `<div>` — dropping the whole card content. `/ajustes` was unaffected only because its Items all use `asChild` (children come from the `<Link>` in `render`). Fixed by forwarding `children: childRender ? undefined : children` into the `useRender` props, mirroring `SidebarMenuButton`. Any `useRender`-based primitive here must forward children the same way.

**Button compatibility aliases:** `default` maps to `primary` and `accent` maps to `tertiary` only so older integrations do not break during the migration. New call sites must use the six semantic variants above; remove aliases after the remaining external/generated integrations no longer reference them.

**Native controls & the single Select** (2026-07-15): the app now sets CSS `color-scheme` (`light` on `:root`, `dark` on `.dark`) so UA-rendered controls (dropdown popups, scrollbars) follow the theme — before this, native `<select>` popups rendered as white OS menus in dark mode. Every dropdown is the **one** design-system `Select` (`components/ui/select.tsx`, Base UI); raw `<select>` is retired. Migration notes: it works uncontrolled (`name` + `defaultValue`) or controlled (`value` + `onValueChange`, which yields `string | null` — coalesce), and posts in native `<form>`s via a hidden input; pass **`items`** (a `{value: label}` map) to the Root whenever the value ≠ its label (e.g. team id → name) so the trigger shows the label while the popup is closed. `""` is a valid item value (used for "Compartilhada"/"Não atribuído").

### 9.5 Hydration & theme — QA-01 resolution (2026-07-11 audit)

Diagnosed per the audit plan: in a **clean browser** (no extensions), light and dark saved preferences, OS preference, first authenticated load, navigation and refresh all hydrate with **zero console errors**. The audit's mismatch (QA-01) reproduces only with the auditor's browser extension injecting `chrome-extension://…/youtube-hulu-vast-ads.js` into `<head>` — QA-01b confirmed; not a `themeScript` bug. The inline theme script stays as-is; `suppressHydrationWarning` on `<html>` (app/layout.tsx) is the narrowest justified boundary — it covers exactly the pre-paint `.dark` class the no-FOUC script adds — and no broader suppression was added. A DOM-level regression test would require a browser-test dependency the repo deliberately doesn't carry; the manual matrix above is the documented verification, and any future hydration error in a clean browser should be treated as a new bug, not as this known issue.
