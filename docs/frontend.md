## 1. Principles

- One question drives everything: **"am I in control of AI spend?"** answered in ≤10s.
- **Verdict-first**: the screen states the conclusion (one deterministic sentence + color); details justify it below.
- Money headlines; tokens are drill-down. Semaphore colors (green/amber/red) are **reserved for budget status** — deltas and everything else stay neutral.
- Honesty in the chrome: "as of <date>" stamps, stale banners, "uncosted", disclosed FX. Never a number the system can't defend.
- Control, not surveillance: per-person data only in context ("contributors to this spike"), names Admin-only.

## 3. Home component contracts

1. **Onboarding checklist** (dismissible, 4 steps, budget step pushed) — only until complete.
2. **Stale-data banner** — only when a connector hasn't synced >1 day.
3. **Verdict line** — always present; green/amber/red; sentence + meta (days left, projection).
4. **Hero**: org spend big number (the product's identity — never demote it to a KPI tile) with a **week-over-week delta pill** under it (rounded neutral pill, `▲ +12% vs semana anterior` — reported `cost_daily` through the digest's own `weekOverWeek`, so screen and email never disagree; NEUTRAL per P5, hidden when the previous week has no spend); paired bars **Gasto % × Mês (dia N de M)** with aligned budget marker; ghost extension = projection; KPI strip (projection / projected margin / day of month) + projected-margin callout. **Read-only** since 2026-07-09 — no inline pencil. The pair renders as **segmented tick bars** (2026-07 restyle: full-width `repeating-linear-gradient` tick layers cut by `clip-path` so the tick grid stays aligned) — texture only; the spend fill keeps the semaphore color (P5), the time bar stays neutral, and `barGeometry` is unchanged. The spend bar is THE bar of the cockpit: taller (`h-4`) and bold (3px ticks on the same 6px grid — `TICKS_BOLD` in `lib/bars.ts`); every other bar in the app, `BudgetBar` included, shares the standard tick texture (2026-07-14 unification).
5. **Orçamentos por time (table)**: ONE stable table for every budgeted team, at-risk first (cockpit ordering). Columns: Time (+ muted warning line for at-risk) · Situação (status pill) · Gasto · Orçamento · Consumo (bar + %) · Projeção · chevron. No expanding rows, no collapsed "Sob controle" group, no inline actions — the whole row links to `/times?focus=<id>` (the team's diagnosis card, expanded and scrolled to — Fase 1, 2026-07-16); a single "Gerenciar orçamentos" action heads to `/ajustes/orcamentos`. (Replaced the rich `TeamRow` + `UnderControl` collapse.) Since Fase 1 the table is **Home-only** (`components/domain/team-budget-table.tsx` — Times replaced it with diagnosis cards); Fase 2 will replace it on Home with the triage rows. Variant switching is **container-query based** (`@container` on the CardContent; compact card list below `@2xl` of the card, table above, Consumo bar column from `@3xl`); Home forces `variant="table"` so the half-width cockpit cell never changes design as the window resizes.
6. **Observações**: calm feed (no red, no urgency), includes unattributed nudge.
7. **Dashboard panels**: "Para onde vai o dinheiro" (provider/seat composition as **ranked horizontal tick bars** with provider brand marks — the donut was retired 2026-07-14; neutral chart-ramp colors, share-cut fills, beside the hero; since 2026-07-16 a CardFooter reconciliation line disclosing the team-cut unattributed amount inside the slices — never a fourth slice, that would double-count — hidden at cents-zero, FX-missing disclosed, linking to Atribuição) and the monthly pace line (bottom-left grid cell, current spend + linear projection). Team distribution stays in the teams table, not as a second composition panel. The 2x2 grid uses **a content-sized top row and a flexible bottom row** (`xl:grid-rows-[auto_minmax(0,1fr)]`, compact 16px gaps — proportion pass 2026-07-14): the dense hero sets row 1's height (its callout flows right after the KPIs — no `mt-auto` pin, so no mid-card void) and the composition card distributes its total + entry list over that same height (`justify-evenly`, not centered). Row 2 absorbs every leftover viewport pixel and the pace plot grows with it (`h-full`, `min-h-[220px]`) — extra height becomes chart, not voids inside the top cards. On a 1920-wide desktop the cockpit fills the viewport without page scroll; narrower desktops (~1440) scroll only as far as the teams card list needs.

**States that must exist:** cold-start (no data/budget → CTA hero, never empty), collecting-pace (before day 5), **all-clear** ("✓ Tudo sob controle · próximo digest sexta"), stale-data, breached. Since 2026-07-15 the **all-clear and stale-data states render in the sidebar** (see §5, `SidebarNotice`), not in the Home column — they are chrome, standing on every route, and a "nothing to do" card should not push the cockpit grid down. Home keeps the verdict line as its affirmative answer.

**#19 implementation:** the page is a Server Component reading `getHomeData()` (`lib/home/queries.ts`), which gathers raw spend parts under RLS and hands them to the pure engine `buildCockpit()` (`lib/engine/cockpit.ts`) — all arithmetic, the seats+API frozen-FX combine, the verdict, the per-team findings, and the needs-attention/under-control partition live there, not in the components (architecture §9). The org spend headline uses provider-**reported** cost (`cost_daily`, the USD source of truth); per-team spend uses **derived** cost (`usage_daily`, the only grain with team attribution). Provider composition converts each provider's reported USD at the org frozen FX and adds the seat slice; when FX is missing the API cost is dropped from the list and disclosed as unconverted (never mixed currencies). New cross-screen domain components: `VerdictLine`, `StatusPill`, `BudgetBar` (fill + dashed run-rate ghost + budget marker, geometry in the pure `lib/bars.ts`).

## 4. Design tokens (implemented in `app/globals.css`)

> Every color is a CSS variable, redefined under `:root` (light) and `.dark` (dark), so re-skinning is a token edit, not a component rewrite.

| Token | Value |
|---|---|
| Brand accent | shadcn preset `b3lVLrQZM` **orange ramp** — primary `oklch(0.553 0.195 38.402)` in light mode and `oklch(0.47 0.157 37.304)` in dark mode; neutral focus rings remain separate from brand color |
| Brand hover accent | `--primary-hover` (`text-primary-hover` / `border-primary-hover`): one step lighter than primary — light `oklch(0.646 0.222 41.116)`, dark `oklch(0.705 0.213 47.604)`. Used by every orange **hover** state (row-name text, card borders, description links) so hovering brightens instead of muddying on the dark card; solid buttons keep the standard `bg-primary/80` press-dim. |
| Brand accent **as text** | Dark `--primary` is a **fill** orange, not an ink: as text on the dark card/popover it measures **2.4:1** — it fails AA and gets *worse* on `hover:bg-muted` (2.1:1). Resting brand text must therefore be `text-primary dark:text-primary-hover` (light 5.2:1, dark 6.1:1), the same split `Button`'s `accent` variant makes. `text-primary` alone is only safe on a light surface, or as a color that sits on a `--primary` fill (that's `--primary-foreground`). |
| Semaphore | **formalized as tokens, three roles per color** (`--status-{green,amber,red}` strong = bar fills/dots · `-soft` = pill/callout backgrounds · `-fg` = text on a soft background), exposed as Tailwind utilities (`bg-status-green`, `text-status-red-fg`, …) via `@theme`. Light: green `#16a34a` · amber `#d97706` · red `#dc2626`; dark uses brighter fills (`#22c55e`/`#f59e0b`/`#ef4444`) for legibility. Reserved for budget status (principle #5) — form success messages are **neutral**, never green (see `ActionStatus`). |
| Surfaces (light) | Stone-based preset: white page/card, warm near-black ink, warm muted surfaces and borders — no blue/slate cast |
| Surfaces (dark) | Stone-based preset: warm near-black page, lifted dark card/popover, warm muted surfaces and borders |
| Sidebar rail | Preset Stone sidebar tokens in both themes; the rail remains visually quieter than the content and uses the orange ramp only for active emphasis |
| Radii | Preset base radius `0.625rem`, expanded through the shadcn scale: compact controls, 10px cards/inner panels and full pills/avatars. Primitives remain `base-mira` with local compatibility for existing `asChild` call sites. |
| Type | DM Sans for app text (`--font-sans`; `--font-heading` maps to sans); Geist Mono (`--font-mono`) only for key-like strings (Admin key input); numbers **tabular-nums**; two weights (400/600) |
| Shadows | cards `shadow-xs`; drawer/modal stronger |
| Content column | one `PageContainer` system, two widths only (founder 2026-07-11): `full` = `max-w-none` exclusively for the Home cockpit (fills the monitor — the big spend number is the product identity); `wide` = `max-w-7xl` (the default) for EVERY other screen — Explorar, team detail, Ajustes and its subpages, Configurações. No width jumps between routes (audit S7/QA-12). All share the same gutters and centering. |

**Light + dark** (supersedes the earlier "light only" of P9). The theme is the `.dark` class on `<html>`, toggled by `components/domain/theme-toggle.tsx` (no dependency; reads/writes `localStorage.theme` and is applied pre-paint by a no-FOUC inline script in `app/layout.tsx`, defaulting to the OS preference). Desktop-first; consumption screens legible at mobile width. Copy: pt-BR, sentence case, observation language for apontamentos, alarm language reserved for warnings.

**Personal settings:** `/configuracoes` is a real authenticated route, but it is accessed from the profile pop-up in the sidebar footer rather than the main nav. It lets the signed-in user edit their own display name, shows email/role as read-only, renders a profile avatar from initials (no file upload/storage in this slice), and reuses the existing local `ThemeToggle`. Company settings stay in **Ajustes**: Admins can edit the tenant name there, while display currency remains read-only to avoid dishonest FX/budget reinterpretation.

**Brand logo** (`components/domain/logo.tsx`): the wordmark is used **extensively** (auth, onboarding, brand panel, sidebar) and is two-tone — the coin is the brand accent (`var(--primary)`), the letters inherit `currentColor` so they theme with the container. In the sidebar it **collapses to the coin mark alone** when the rail is in icon mode.

## 5. Interaction patterns

- **Drawer** (right, 420px): simulator — pre-loaded team, presets (ritmo atual / fechar no orçamento / −30%), slider, instant recompute. Scrim click closes.
- **Confirmation dialog**: required before every Revogar/Remover action; consequence copy, safe initial focus, disabled while pending.
- **Feedback**: field validation remains inline; cross-screen mutation success/error uses a Base UI toast (5 seconds, maximum three, neutral success and destructive error).
- **Invite acceptance** (`/convite/[token]`, 2026-07-15): a public route outside the app shell, reusing the auth split-screen (wordmark + `BrandPanel`). The email is shown read-only — the token proves *that* address — and the only field is the password. A dead link (expired, used, revoked, unknown) renders one calm "peça um novo convite" state with a login link, never a hint about whether the token existed. The one-time invite URL is surfaced to the Admin with a copy button on `/ajustes/usuarios`, because the token is hashed at rest and email delivery may be unconfigured.
- **Sidebar notices** (2026-07-15, founder-directed): every chrome-level notice — the reconnect caveat (`StaleBanner`) and the all-clear (`AllClear`) — wears **one shared shape**, `components/domain/sidebar-notice.tsx`: an `Alert` card in the sidebar footer while expanded, the same `size-8` icon slot on the collapsed rail, both silent when they have nothing to say. Tone is meaning, not decoration: `neutral` for the data-quality voice (never semaphore, principle #5), `green` only for the all-clear, which *is* a budget statement. **A notice only takes the collapsed rail when it has an `href`** — an icon button that does nothing is a mystery, so the linkless all-clear hides on the rail instead of becoming a dead pictogram. The all-clear's `allClear` flag is read in the app layout (`getCockpitData()`); `assembleCockpit` is `react/cache`-memoized per request, so putting cockpit-derived chrome in the layout costs Home and Times **no extra queries** — it does add one assembly to the other routes, accepted deliberately at this data size.
- **Dismissible all-clear**: the affirmative status includes a familiar close icon with an accessible name. Dismissal is local to the current render and uses a short fade/scale exit; it does not alter findings or notification state (invariant #6).
- **Drill** (Fase 1, 2026-07-16 — the separate `/times/[teamId]` page was absorbed): any team row on Home → `/times?focus=<id>`, landing on that team's diagnosis card expanded and scrolled into view (`TeamDiagnosisCard`, the collapse-choreography client island; header and body are server-rendered props). The card body carries the budget context, the ritmo chart, the decomposição, the contributors table (Admin-only **inside** the card — Viewers see the aggregates plus a calm disclosure line, no route-level lockout anymore), the control plan and the [Simular] drawer + inline budget dialog. Home itself never expands or opens a drawer. Person data only inside a diagnosis, framed as "contribuintes deste time". Old `/times/[teamId]` deep links redirect permanently.
- **Motion layer** (updated 2026-07-15): Base UI remains the primitive base. Controls use the preset's restrained one-pixel press response rather than hover lift or icon scaling; popovers/dialogs retain short soft entrances and respect `prefers-reduced-motion`. Do **not** adopt a sliding menu hover indicator; sidebar and menus stay restrained with simple color/focus states. Chart/bar open-animations are handled app-wide by the `RevealController` (see §6), not per-screen. **Sidebar collapse/expand** eases at 320ms `cubic-bezier(0.16,1,0.3,1)` (unlayered `globals.css` overrides on the primitive's `data-slot="sidebar-gap|sidebar-container|sidebar-group-label|sidebar-inset|sidebar-menu-button"` hooks — F5 keeps `components/ui/` untouched; the inset card's `ml-0↔ml-2` flip and the menu buttons' size morph ride the same 320ms clock, and Recharts charts stretch-while-frozen instead of re-rendering per frame, see §6) with labels/wordmark staying mounted and crossfading (fast fade-out on collapse, ~100ms-delayed fade-in on expand; the buttons' `overflow-hidden` clips them mid-transition). Each nav icon and footer control uses an invariant `size-8` visual slot. Expanded spacing lives on the button padding and label margin, while every menu item stays full-width and the shrinking button centers with auto margins. Its expanded width is the fixed rail-relative `calc(var(--sidebar-width) - 2rem)`, never `100%`: a percentage would be recalculated while the parent narrows and compound the interpolation, pulling the icon sideways during collapse. This keeps the icon on one monotonic path into the rail center — see `fadeLabel`/`navButton`/`navIconSlot`/`profileSlot` in `AppSidebar`. **The verdict dot pulses, it never blinks**: `denarius-status-ping` (expanding, fading ring) + `denarius-status-breathe` (subtle dot scale), 2.2s cycle, in the dot's own semaphore color. It runs in **every semaphore state** (green/amber/red — founder-directed 2026-07-15, replacing the earlier red-only rule): at 2.2s the pulse reads as "this reading is live", not as an alarm, so green stays calm. Only `collecting` is motionless — no judgement, no motion, before day 5. The ring's base opacity is 0 so reduced motion leaves it invisible.

- **Sidebar label choreography**: labels, group headings, and the wordmark combine their crossfade with a restrained 4px horizontal drift. Icons do not scale or transform; their invariant slot and monotonic path remain the geometric anchor.

## 6. Charts

- Team/budget bars: HTML/CSS segmented tick bars (semaphore tick fill + neutral tick ghost + marker; texture primitives `TICKS`/`TICKS_BOLD`/`cut` shared from `lib/bars.ts` — 2026-07-14 unification, the solid bar is gone).
- Home dashboard visuals: the provider/seat composition is **ranked horizontal tick bars** (hand-rolled CSS over already computed shares, with `ProviderIcon` brand marks — the Recharts donut was retired 2026-07-14, matching PRD's original "ranked bar list" call); the monthly pace line (shadcn Chart + Recharts) is explicitly current spend plus linear projection, not a historical series. Spend line charts use the light `--chart-1` orange so they stay visually distinct from the red budget semaphore. Chart/bar **open-animations are app-wide** (generalized 2026-07-12): one client `RevealController` (`components/domain/reveal-controller.tsx`), mounted once in the `(app)` layout under `data-reveal-root`, replays construction on every navigation and back-forward restore and starts each target when it enters the viewport (targets that stream in after the pathname effect — Suspense/`loading.tsx`, server-action revalidates — are caught by a MutationObserver on the root; `animationend` flips finished targets to `done` so `will-change` is released) — CSS budget/pacing/composition bars grow from the left and the line charts reveal left-to-right. Server components render the targets via the `data-reveal` / `data-reveal-bar|-wipe|-legend` attribute contract (motion is pure CSS in `globals.css`, `cubic-bezier(0.16,1,0.3,1)`); `prefers-reduced-motion` jumps straight to the final state. **Every `data-reveal` element must also set `suppressHydrationWarning`**: the controller stamps `data-reveal-state` on streamed nodes before their client island hydrates, and without the opt-out React logs a hydration mismatch for the controller-owned attribute. Recharts' own line animation stays disabled (`isAnimationActive={false}`) so the dashed projection stays a single continuous segment, and the big money numbers never count up (calm by default). **Continuous-resize rule (2026-07-15):** per-frame chart re-renders are forbidden during continuous layout animations (the sidebar collapse resizes the whole content column every frame) — both Recharts charts pass `debounce` to `ChartContainer`, which freezes re-renders and lets the frozen SVG **stretch with its container** (`[&_.recharts-surface]:size-full!` + `preserveAspectRatio="none"`, possible because Surface always emits a matching viewBox), then redraws crisp ~80ms after the resize settles.
- Cumulative historical line (spend vs budget + dashed projection): **implemented 2026-07-09**, moved into the Times diagnosis cards in Fase 1 (2026-07-16) — `CumulativeChart` (colocated in `times/_components/`) over the pure `buildCumulativeSpend()` (`lib/engine/cumulative.ts`, unit-tested): real day-by-day series using the same combine as the evaluation (frozen FX, FX-missing drops API, seats spread evenly), so the line's last point IS the card's "Gasto"; dashed tail to `evaluation.projection`; budget `ReferenceLine` labeled; and the **expected-pace diagonal** (Fase 1: pure `expectedPaceSegment()` — the budget spread evenly across the days, finely dotted neutral, so the eye spots the day spend detached from plan; never semaphore-colored). `budget` is nullable — a budget-less team charts spend alone. One chart per card on the same page, so the area-fill gradient id comes from `useId`, never a fixed string. It reveals left-to-right on open via the shared `data-reveal-wipe` wrapper.

## 7. Implementation decisions (F1–F6 — locked)

| # | Question | Status |
|---|---|---|
| F1 | Rendering/data strategy | **LOCKED — RSC-first + server actions.** Pages are Server Components reading Postgres directly; mutations are server actions; no internal REST layer, no React Query, no global state. `"use client"` only for real interactivity (drawer, modal, collapse, slider). Rationale: data changes 1×/day (daily sync); engine is server-side and deterministic; fewer moving parts = easier due-diligence audit. |

Budget bars (tick fill + budget marker + tick ghost), the pacing pair, and provider composition (ranked tick bars since 2026-07-14 — the donut is gone, closing the old F3 inconsistency) are hand-rolled CSS (semantic UI, and Recharts fights the marker/ghost pattern). ## 9. v1 product UI (2026-07) — inventory, state patterns, pendências

### 9.1 shadcn primitives (`components/ui/`)

Base set from #12 (button, input, label, dialog, sheet, dropdown-menu, tooltip, sidebar, skeleton, separator, collapsible, avatar, breadcrumb, field) plus, added in the v1 UI pass: **card, badge, alert, table, select, switch, progress, empty, item, chart**. App icons are standardized on **Remix Icon** via `@remixicon/react`. The app shell runs the `sidebar-08` **inset** look (2026-07-12): `AppSidebar` sets `variant="inset" collapsible="icon"`, so the sidebar and the `SidebarInset` content card float, and the sidebar collapses to an icon + coin-logo rail; the sticky header carries a vertical `Separator` after the collapse toggle and rounds its top corners on `md+` to sit inside the inset card.

**Motion policy** (updated 2026-07-15): shared controls follow the preset's restrained press feedback, while chart/bar construction is controlled app-wide by the `RevealController` + CSS keyframes so it restarts on navigation and viewport entry (Home cockpit and the Explorar team drill-down; the Explorar list and the big money numbers stay static). Keep transitions short and executive-calm. Never use hover lift, icon zoom or a sliding menu hover indicator; menus/sidebar remain simple color/focus interactions. Sidebar collapse choreography and the verdict-dot pulse are specced in §5 (Motion layer): width easing 320ms `cubic-bezier(0.16,1,0.3,1)` via `data-slot` overrides in `globals.css`, mounted-label crossfades, stable icon slots that isolate icon alignment from label layout, and `denarius-status-ping`/`denarius-status-breathe` replacing the old `animate-pulse` blink on `VerdictLine`.

**Base UI dropdown gotchas** (found 2026-07-09 fixing the sidebar profile menu): (1) `DropdownMenuLabel` wraps Base UI `Menu.GroupLabel`, which **throws "MenuGroupContext is missing" outside a `<Menu.Group>`** — for a plain identity header inside the menu, use a styled `<div>`, not `DropdownMenuLabel`. (2) Composing `DropdownMenuTrigger asChild` through another render-prop component (e.g. `SidebarMenuButton`, itself a `TooltipTrigger`) **swallows the trigger's open/close handlers and the menu never opens** — use a plain `DropdownMenuTrigger` (it renders its own native button) styled to match, with an `aria-label` for the collapsed rail.

**Button icon-size gotcha** (found 2026-07-09 — the header sidebar toggle rendered a 12px speck): the `Button` base carries `[&_svg:not([class*='size-'])]:size-3`, whose `:not([class*=…])` gives it **higher specificity than any parent `[&_svg]:size-*` override** — such overrides silently lose. The intended escape hatch is a `size-*` class **on the svg itself** (that's what the `:not()` guard checks). Any icon inside a `Button` that should not be 12px must carry its own size class (e.g. `SidebarTrigger` now renders `<RiSidebarFoldLine className="size-5" />`).

**`asChild`-from-a-Server-Component gotcha** (found 2026-07-15 — the "Definir orçamentos" button on `/times` rendered as an empty stub and the hydration mismatch garbled the card): an element passed as `asChild` children **from a Server Component** arrives at the client primitive as a `react.lazy` element (react#32392). Base UI's `evaluateRenderProp` merges the primitive's props with `render.props` *before* unwrapping the lazy element — `render.props` is `undefined` at that point — so any explicit `children` key on the primitive, **even `null`**, wins in `cloneElement` and wipes the render element's label out of the SSR HTML. Client-component call sites are unaffected (their elements are local, `render.props.children` survives), which is why the bug hides: identical JSX works on one screen and breaks on another. Fix pattern (applied to `Button`): when `render` is set, omit the `children` key entirely (`{...(render ? {} : { children })}`), never pass `{render ? null : children}` as a JSX child. `dropdown-menu.tsx`/`sidebar.tsx` still carry the generated null-children pattern but are only composed from client components today — apply the same fix there if a server component ever feeds them an `asChild` element.

**`Item` primitive gotcha** (found 2026-07-09 — `/configuracoes` rendered a blank card): `Item` is built on Base UI `useRender`, which only renders children it receives via `props`. The generated component destructured `children` out and never forwarded it, so a plain `<Item>…</Item>` (no `asChild`) rendered an empty `<div>` — dropping the whole card content. `/ajustes` was unaffected only because its Items all use `asChild` (children come from the `<Link>` in `render`). Fixed by forwarding `children: childRender ? undefined : children` into the `useRender` props, mirroring `SidebarMenuButton`. Any `useRender`-based primitive here must forward children the same way.

**Button `accent` variant** (added 2026-07-15): a tonal brand pill — `bg-primary/10 text-primary` (dark `bg-primary/15 text-primary-hover`) — for the one "save the CEO time" affordance (`NextActionsButton`). It is *not* a semaphore green/red and stays distinct from the solid `default` (`bg-primary`) and the neutral `outline`/`ghost`; reach for it only when a control is the primary shortcut on a screen, never as a second solid button.

**Native controls & the single Select** (2026-07-15): the app now sets CSS `color-scheme` (`light` on `:root`, `dark` on `.dark`) so UA-rendered controls (dropdown popups, scrollbars) follow the theme — before this, native `<select>` popups rendered as white OS menus in dark mode. Every dropdown is the **one** design-system `Select` (`components/ui/select.tsx`, Base UI); raw `<select>` is retired. Migration notes: it works uncontrolled (`name` + `defaultValue`) or controlled (`value` + `onValueChange`, which yields `string | null` — coalesce), and posts in native `<form>`s via a hidden input; pass **`items`** (a `{value: label}` map) to the Root whenever the value ≠ its label (e.g. team id → name) so the trigger shows the label while the popup is closed. `""` is a valid item value (used for "Compartilhada"/"Não atribuído").

### 9.3 State patterns (required states, §3, now uniform)

### 9.5 Hydration & theme — QA-01 resolution (2026-07-11 audit)

Diagnosed per the audit plan: in a **clean browser** (no extensions), light and dark saved preferences, OS preference, first authenticated load, navigation and refresh all hydrate with **zero console errors**. The audit's mismatch (QA-01) reproduces only with the auditor's browser extension injecting `chrome-extension://…/youtube-hulu-vast-ads.js` into `<head>` — QA-01b confirmed; not a `themeScript` bug. The inline theme script stays as-is; `suppressHydrationWarning` on `<html>` (app/layout.tsx) is the narrowest justified boundary — it covers exactly the pre-paint `.dark` class the no-FOUC script adds — and no broader suppression was added. A DOM-level regression test would require a browser-test dependency the repo deliberately doesn't carry; the manual matrix above is the documented verification, and any future hydration error in a clean browser should be treated as a new bug, not as this known issue.
