## 1. Principles

- One question drives everything: **"am I in control of AI spend?"** answered in ≤10s.
- **Verdict-first**: the screen states the conclusion (one deterministic sentence + color); details justify it below.
- Money headlines; tokens are drill-down. Semaphore colors (green/amber/red) are **reserved for budget status** — deltas and everything else stay neutral.
- Honesty in the chrome: "as of <date>" stamps, stale banners, "uncosted", disclosed FX. Never a number the system can't defend.
- Control, not surveillance: per-person data only in context ("contributors to this spike"), names Admin-only.

## 3. Home component contracts

1. **Onboarding checklist** (`SetupChecklist`, implemented 2026-07-20): three steps (connect a provider · import the roster · set the budget) with numbered/checked markers and an "N de 3 concluídos" progress meta. Full card under the cold-start hero; a **compact strip between the verdict line and the grid on ready Home** while any step is missing (a verdict can exist with the roster still pending). It disappears by **completion, not dismissal** — no persisted state. Non-blocking always.
2. **Stale-data banner** — only when a connector hasn't synced >1 day.
3. **Verdict line** — always present; green/amber/red; one SHORT deterministic sentence (2026-07-17 de-noise: red names the breached team and its **own** overrun — "Engenharia ultrapassou o orçamento em 19%."; amber/green carry only the projected delta, no close date). On a team-red verdict the engine exposes `verdict.teamId` and the line renders an optional **"Ver time →"** contextual action (`VerdictLine`'s `action` prop, neutral `tertiary` button at rest and hover) to `/times/<id>`. The UI never re-derives the breached team — it must match the sentence's tie-break.
4. **Hero** (de-noised 2026-07-17, founder-directed): card title **"Gasto do mês"** (regular L2 card title, no longer a muted description) over the org spend big number (the product's identity — never demote it to a KPI tile; it now dominates by SUBTRACTION, not enlargement) with a **week-over-week delta pill** under it (rounded neutral pill, `▲ +12% vs semana anterior` — reported `cost_daily` through the digest's own `weekOverWeek`, so screen and email never disagree; NEUTRAL per P5, hidden when the previous week has no spend **or |Δ| < 0,5%** — a "0,0%" chip is noise); then **ONE pacing bar** (`PacingBar`, replacing the old `PacingPair` two-bar stack): an `h-8` `TICKS_BOLD` bar in **three tones** (2026-08-01, founder-directed) — spend at full brand accent, the run-rate projection at the SAME hue weakened to 38%, and the untouched remainder neutral at 12%. An accent ramp rather than three hues, because §4 caps orange at a few anchors per area and reserves green/amber/red for budget status (principle #5); the weakened-accent projection is also exactly what `SpendTrendChart` does for its projected series, so bar and chart read as one language. **38%, not the 55% first tried**: two tones of one hue separate by lightness alone, and at 55% the two halves blended into a single smear. On a realized breach (`pctSpent > 1`) the fill turns red **and the projection follows it** — a red bar trailing an orange projection would read as two different claims. The budget rule (`bg-foreground/80`) is the bar's **one** reference mark. The elapsed-time position was briefly a second rule inside the bar and then removed (founder-directed): the comparison it served now lives in the meta row above, where `dia N de M` sits beside `% gasto` — the two figures the bar exists to compare, side by side, instead of a mark to decode. That row also replaced the old date absolutely positioned at the elapsed offset *under* the bar, anchored to nothing. `pctElapsed` still feeds the accessible description, which states both figures. `barGeometry` unchanged.
   **Legend on hover only** (founder-directed, trade-off accepted): swatches for Gasto · Projeção · Orçamento fade in on `group-hover`, absolutely positioned so revealing them costs no reflow, and each swatch is shaped like the mark it names — the rules are drawn as rules, and the neutral track carries no label because it is simply room not yet claimed (calling that grey "Orçamento" would name two different marks the same thing). It is invisible to a glance and unreachable on touch, so an always-present `sr-only` sentence carries the same content; assistive tech must never depend on a pointer. `PacingBar` stays a **Server Component** — the hover is pure CSS, same precedent as `RankedTickList`. Below the bar, a **single KPI** — "Projeção de fechamento" (emphasis weight, neutral ink) — the projected margin's home is now the verdict sentence, and the old projected-margin KPI + callout sentence were removed as duplicates. The unconverted-USD honesty footer stays (invariant #4, never a tooltip). **Read-only** since 2026-07-09 — no inline pencil. The day-of-month meta line left the page's top-right corner: the "hoje" marker is its one canonical home (only the quiet `dados de <stamp>` freshness stamp remains up there, per principle #3).
5. **Orçamento dos times (table)**: ONE stable table for every budgeted team, at-risk first (cockpit ordering). Columns: Time · Situação (status pill) · Gasto · Orçamento · Consumo (bar + %) · Projeção · chevron. The permanent warning sentence under at-risk names was **removed in the 2026-07-17 de-noise** — the pill IS the resting signal; its full reason (`warnBreach`/`warnProjected`/`warnThreshold`) now lives in a **tooltip on the pill** (`TeamStatus`, click-stopped so a tap on the chip reveals the reason instead of navigating). Row dividers use `border-border/60`. No expanding rows or inline actions — the whole row links to `/times/<id>`; a single "Gerenciar orçamentos" action heads to `/ajustes/orcamentos`. The table is Home-only; Times owns its denser comparable index. Variant switching is container-query based (`@container` on the CardContent; compact list below `@2xl`, table above, Consumo from `@3xl`); Home forces `variant="table"`.
6. **Observações**: calm feed (no red, no urgency), includes unattributed nudge.
7. **Dashboard panels** (titles standardized + de-noised 2026-07-17): **"Gasto por fonte"** remains the ranked provider/seat tick-bar list with the compact unattributed notice; **"Evolução do mês"** is the direct-Recharts cumulative area + projection chart in the bottom-left grid cell. The chart keeps a title-side `InfoTip`, the labeled Hoje marker, the neutral budget reference, and an orange projected-close endpoint; its permanent close and budget labels are separated and aligned inward so they never read as the same value. Team distribution stays in the teams table. The 2x2 grid retains its content-sized top row, flexible bottom row, 16px gaps, and `min-h-[220px]` pace plot; no chart refinement changes card height or dashboard layout.

**States that must exist:** cold-start (no data/budget → CTA hero, never empty), collecting-pace (before day 5), **all-clear** ("✓ Tudo sob controle · próximo digest sexta"), stale-data, breached. Since 2026-07-15 the **all-clear and stale-data states render in the sidebar** (see §5, `SidebarNotice`), not in the Home column — they are chrome, standing on every route, and a "nothing to do" card should not push the cockpit grid down. Home keeps the verdict line as its affirmative answer.

**#19 implementation:** the page is a Server Component reading `getHomeData()` (`lib/home/queries.ts`), which gathers raw spend parts under RLS and hands them to the pure engine `buildCockpit()` (`lib/engine/cockpit.ts`) — all arithmetic, the seats+API frozen-FX combine, the verdict, the per-team findings, and the needs-attention/under-control partition live there, not in the components (architecture §9). The org spend headline uses provider-**reported** cost (`cost_daily`, the USD source of truth); per-team spend uses **derived** cost (`usage_daily`, the only grain with team attribution). Provider composition converts each provider's reported USD at the org frozen FX and adds the seat slice; when FX is missing the API cost is dropped from the list and disclosed as unconverted (never mixed currencies). New cross-screen domain components: `VerdictLine`, `StatusPill`, `BudgetBar` (fill + dashed run-rate ghost + budget marker, geometry in the pure `lib/bars.ts`).

## 5. Interaction patterns

### Button system (2026-07-17)

All product actions use `components/ui/button.tsx`, backed by Base UI + CVA. Do not recreate button chrome at call sites: `className` is for positioning or a narrowly scoped composition adjustment only. The internal reference page is `/ajustes/botoes`.

| Variant | Use | Resting treatment |
|---|---|---|
| `primary` | The one main action in a screen, form or dialog | Brand-orange fill, high-contrast ink |
| `secondary` | Important global or supporting action | Neutral fill + subtle border |
| `tertiary` | Contextual card, alert or row action | Near-transparent neutral surface; hover lifts the neutral surface/border while only its icon or chevron may use `accent-light` |
| `ghost` | Navigation, menus and icon-only controls | No resting surface or border |
| `destructive` | Irreversible delete/remove/revoke only | Destructive red treatment |
| `outline` | Alternative action in a form/dialog | Transparent neutral surface + border |

Sizes are fixed: `sm` 28px (14px icons), `default` 36px (16px icons), `lg` 40px, `icon` 36×36px and `icon-sm` 28×28px. Primary and secondary actions use the 14px `lg` radius; compact contextual actions opt into the `pill` shape; icon-only sizes are circular. Right-side navigation uses the same Remix `RiArrowRightSLine` chevron and inherited size everywhere. `loading` + `loadingText` keeps the control width stable, sets `aria-busy`, disables repeat interaction and renders the local Loading UI `Spokes` component (`components/loading-ui/spokes.tsx`), inheriting the button color and stopping under reduced motion. Icon-only buttons require `aria-label`; native `type` remains explicit at submit/reset call sites.

### Button motion (2026-07-18)

Button motion is centralized in `Button` and is driven by action intent, never by control size. The shared tokens are `--motion-duration-fast: 120ms`, `--motion-duration-standard: 160ms`, `--motion-duration-max: 180ms`, `--motion-ease-standard: cubic-bezier(0.22,1,0.36,1)`, `--motion-icon-shift: 3px` and `--motion-button-lift: 1px`.

**App-wide motion rule (2026-07-18 standardization):** every interaction-speed transition consumes these tokens — micro moves (chevrons, icon shifts, color fades on small marks) at `fast`, hover/row/content color at `standard`, overlay enter/exit (dropdown, popover, select, tooltip, dialog, sheet) at `max` — written as `duration-(--motion-duration-*)` + `ease-(--motion-ease-standard)` utilities (or the CSS vars directly). No raw `duration-150/200/300` and no `transition-all` in first-party code. Signature motion is the deliberate exception and uses `--motion-ease-expressive: cubic-bezier(0.16,1,0.3,1)`: the 320ms sidebar collapse, the chart reveal builds (560–1400ms), the 2200ms verdict pulse and the auth entrance. Focus rings are uniformly `focus-visible:ring-2 ring-ring/40`.

| Intent | Hover | Active | Focus |
|---|---|---|---|
| `primary` | Background gains contrast and the container rises at most 1px | Returns through the origin and presses down at most 1px | Stable accent ring; no movement |
| `secondary` / `outline` | Neutral surface, border and ink gain restrained contrast | Surface darkens slightly; container stays fixed | Stable accent ring; no movement |
| `tertiary` / contextual | 120ms neutral surface/border transition; only a semantic end chevron may gain accent-light and move | Directional icon falls back to a 1px displacement; container stays fixed | Stable accent ring; no movement |
| `destructive` | Controlled red surface/border contrast only | Surface pressure only; no shake, pulse or glow | Stable destructive ring; no movement |
| icon-only | Surface/contrast by default; movement only when the icon's meaning requires it | Semantic feedback only | Stable ring; no movement |

Directional controls opt into `motion="forward"` or `motion="backward"`, and mark only the semantic arrow with `data-icon="inline-end"` or `data-icon="inline-start"`. Disclosure controls use `motion="disclosure"` plus `data-icon="disclosure"`, rotating only that chevron while `aria-expanded=true`. This keeps labels and unrelated icons still. Hover displacement runs only on devices that actually support hover; touch receives the short active response. Loading keeps the original content in layout at zero opacity, centers an overlaid spinner, sets `disabled` + `aria-busy` and suppresses hover/active transforms. Disabled controls likewise have no movement or hover interaction. Under `prefers-reduced-motion`, elevation, directional displacement, disclosure rotation and spinner rotation are removed; only the short color/background/opacity transitions remain.

The internal `/ajustes/botoes` reference renders hover, active, keyboard focus, loading and disabled examples for direct inspection. This intent-based policy supersedes any earlier generic press-motion wording.

Controls use the preset's restrained one-pixel press response rather than hover lift or icon scaling; popovers/dialogs retain short soft entrances and respect `prefers-reduced-motion`. It runs in **every semaphore state** (green/amber/red — founder-directed 2026-07-15, replacing the earlier red-only rule): at 2.2s the pulse reads as "this reading is live", not as an alarm, so green stays calm. Only `collecting` is motionless — no judgement, no motion, before day 5. The ring's base opacity is 0 so reduced motion leaves it invisible.

## 6. Charts

- **Shared trend chart + hover focus (2026-08-01, founder-directed from a reference recording).** `components/domain/spend-trend-chart.tsx` owns the chart *grammar* for both spend-over-time charts (Home "Evolução do mês" and the Times drill-down): `ChartContainer` with `debounce={80}`, the `SpendChartGrid`/`SpendAreaGradient` visuals, the shared margins (`top 28 · right 28 · bottom 6 · left 4`), `YAxis width={68}`, the bold-today `DayTick`, one gradient `Area` plus any number of dashed companion `Line`s. Screens keep their engine rows, their pt-BR copy and their tooltip content (F2, invariant #2) and pass extras (`ReferenceDot`, labels) as children.
  The **hover focus** replaces Recharts' dashed cursor (`cursor={false}`). Four parts:
  1. **Veil (`FocusScrim`) + highlight (`HighlightLayer`)** — two deliberately separate layers. The veil is a plain page-coloured rect over the plot at 0.62 opacity that dims grid, area fill and every series **evenly**. It only becomes visible when Recharts reports both an active tooltip and a finite hover coordinate. The SVG itself renders the safe `opacity` value (`0` or `0.62`) while `data-visible` remains diagnostic; CSS owns only the fade. This prevents a stale stylesheet from reverting the rect to SVG's opaque default and erasing the plot. The highlight is a full-strength, stroke-only **copy of each series** drawn on top, revealed through a responsive 2-day window (`HIGHLIGHT_DAY_SPAN`), with feathering capped at 4px. Redrawing the line gives the lit stretch a defined edge instead of making it a soft hole in the veil.
  **Three ordering facts, all load-bearing.** SVG has no `z-index`, so the layers use Recharts' `ZIndexLayer` — veil at **700** (above grid −100, area 100, lines 400, reference dots 600), highlight at **800**, both below the tooltip layers (1000+). `zIndex={0}` on the duplicated `<Area>`/`<Line>` is what keeps them *inside* the masked group: Recharts otherwise portals every series into its own layer, which would yank them straight back out. And the veil bleeds `SCRIM_BLEED` 10px past the plot box, otherwise an edge-anchored mark (the projected-close dot) is veiled on one half and lit on the other. The axis needs no ordering — it is outside the rect geometrically.
  2. **Hairline** — 2px accent rule at the hovered day, clip-path **tapered to a point at both ends**, so it reads as an indicator spanning the plot rather than a rule crossing it.
  3. **Axis pill** — **gray** `bg-muted`, centred on the hovered day, covering the static tick it stands in for.
  4. **Focus dot** — sits on the series at the hovered day and **glides along the line** with the rest of the focus, and the tooltip carries its date as a caption *above* the dark panel.
  All three overlays are DOM, not SVG, so the pill gets real typography and design-system tokens; a null-rendering bridge inside the chart reads `useIsTooltipActive`/`useActiveTooltipCoordinate`/`useActiveTooltipLabel`/`usePlotArea`/`useYAxisScale` (Recharts 3 hooks) and writes transforms straight to the nodes — **the hovered day never becomes React state**, so moving the cursor re-renders neither the plot nor the screen. The highlight window rides the same bridge: a fixed-shape mask that is *translated*, because `transform` is CSS-animatable where recomputed gradient stops are not.
  **Motion separates response from polish** (revised 2026-08-01): the hairline, focus dot and axis pill respond in 90ms with `ease-out`, removing the bug-like pointer lag. The horizontal highlight trails in 150ms **on the same `ease-out` curve, with no delay**. Both halves of that are measured, not taste: the first attempt (260ms + a 35ms head start, expressive easing) left the two **223px apart 40ms into a jump** and still 28px apart at 120ms, so the ruler arrived and the highlight crawled after it — which reads as stuttering, not trailing. Frame timing was clean throughout (median 16.7ms, nothing over 24ms), so the SVG mask was never the cost; the desync was. Giving the highlight the expressive ease at 150ms then made it *lead* the ruler by ~100px — a desync the other way. Sharing the ruler's curve and only lengthening it makes the highlight always trail and converge (~120ms). The Recharts tooltip stays free on both axes and uses its own short 120ms `ease-out` transition with automatic edge avoidance. The overlays fade in over `--chart-focus-fade` 120ms, but the **veil settles over its own `--chart-veil-fade` 260ms `ease-in-out`**: entering the dimmed state is a change of mode, not a follow, so it is the one moment here meant to be felt rather than merely fast.
  **Annotations sit above the veil.** Reference dots and their labels are passed in as `children`, and callers must give every `ReferenceDot` `CHART_ANNOTATION_Z_INDEX` (900 — above the veil at 700 and the lit copy at 800, below the tooltip). Recharts defaults them to 600, *under* the veil, and a label rendered through a custom `content` stays in the dot's layer instead of reaching `Label`'s own 2000 — which is how the projected-close figure ended up dimmed by the very veil that exists to make the hovered stretch legible. These are honesty stamps (principle #3); the focus must never obscure them. Motion lives in `.denarius-chart-focus`, `.denarius-chart-scrim` and `.denarius-chart-window` (globals.css) behind `prefers-reduced-motion: no-preference` — reduced motion keeps the focus and drops movement; transition is suppressed when the focus reappears so nothing slides in from a stale position.
  The plot shows a **crosshair cursor**. `cursor-crosshair` on the ChartContainer was not enough — Recharts' own wrapper sets a cursor that beat the utility — so the rule lives unlayered in globals.css against `.recharts-wrapper`/`.recharts-surface` (F5 keeps `components/ui` untouched).
  **Why the dot is ours and not Recharts'.** `activeDot={false}` on every series; `HoverFocus` resolves the point itself — first series with a value at the hovered day (the area wins ties, e.g. the shared realized/projected vertex at "today"), mapped through `useYAxisScale()`, hidden when every series is null there. Recharts' own dot cannot glide: Chrome does not transition `cx`/`cy` written as SVG presentation attributes, and a dot that teleports while the hairline and the lit window slide breaks the illusion of one continuous line. The dot is coloured from the `config` entry of the series it landed on — a projected day is never painted as if it had already happened — read from `config` rather than the `--color-<key>` variables, which `ChartStyle` scopes to the ChartContainer the overlays sit outside of. The trade: one dot instead of one per series, matching the reference; every series still appears in the tooltip.

Bars are **brand-accent orange** (founder-directed): composition is not budget status, and orange is the brand accent, never a verdict color (principle #5). **Motion policy** (updated 2026-07-18): shared controls follow the preset's restrained press feedback, while chart/bar construction is controlled app-wide by the `RevealController` + CSS keyframes so it restarts on navigation and viewport entry (Home cockpit, Explorar ranked tick bars and the team drill-down; big money numbers stay static). Keep transitions short and executive-calm. Never use hover lift, icon zoom or a sliding menu hover indicator; menus/sidebar remain simple color/focus interactions. Sidebar collapse choreography and the verdict-dot pulse are specced in §5 (Motion layer): width easing 320ms `cubic-bezier(0.16,1,0.3,1)` via `data-slot` overrides in `globals.css`, mounted-label crossfades, stable icon slots that isolate icon alignment from label layout, and `denarius-status-ping`/`denarius-status-breathe` replacing the old `animate-pulse` blink on `VerdictLine`.

**Base UI dropdown gotchas** (found 2026-07-09 fixing the sidebar profile menu): (1) `DropdownMenuLabel` wraps Base UI `Menu.GroupLabel`, which **throws "MenuGroupContext is missing" outside a `<Menu.Group>`** — for a plain identity header inside the menu, use a styled `<div>`, not `DropdownMenuLabel`. (2) Composing `DropdownMenuTrigger asChild` through another render-prop component (e.g. `SidebarMenuButton`, itself a `TooltipTrigger`) **swallows the trigger's open/close handlers and the menu never opens** — use a plain `DropdownMenuTrigger` (it renders its own native button) styled to match, with an `aria-label` for the collapsed rail.

**Button icon-size gotcha** (found 2026-07-09 — the header sidebar toggle rendered a 12px speck): the `Button` base carries `[&_svg:not([class*='size-'])]:size-3`, whose `:not([class*=…])` gives it **higher specificity than any parent `[&_svg]:size-*` override** — such overrides silently lose. The intended escape hatch is a `size-*` class **on the svg itself** (that's what the `:not()` guard checks). Any icon inside a `Button` that should not be 12px must carry its own size class (e.g. `SidebarTrigger` now renders `<RiSidebarFoldLine className="size-5" />`).

**`asChild`-from-a-Server-Component gotcha** (found 2026-07-15 — the "Definir orçamentos" button on `/times` rendered as an empty stub and the hydration mismatch garbled the card): an element passed as `asChild` children **from a Server Component** arrives at the client primitive as a `react.lazy` element (react#32392). Base UI's `evaluateRenderProp` merges the primitive's props with `render.props` *before* unwrapping the lazy element — `render.props` is `undefined` at that point — so any explicit `children` key on the primitive, **even `null`**, wins in `cloneElement` and wipes the render element's label out of the SSR HTML. Client-component call sites are unaffected (their elements are local, `render.props.children` survives), which is why the bug hides: identical JSX works on one screen and breaks on another. Fix pattern (applied to `Button`): when `render` is set, omit the `children` key entirely (`{...(render ? {} : { children })}`), never pass `{render ? null : children}` as a JSX child. `dropdown-menu.tsx`/`sidebar.tsx` still carry the generated null-children pattern but are only composed from client components today — apply the same fix there if a server component ever feeds them an `asChild` element.

**`Item` primitive gotcha** (found 2026-07-09 — `/configuracoes` rendered a blank card): `Item` is built on Base UI `useRender`, which only renders children it receives via `props`. The generated component destructured `children` out and never forwarded it, so a plain `<Item>…</Item>` (no `asChild`) rendered an empty `<div>` — dropping the whole card content. `/ajustes` was unaffected only because its Items all use `asChild` (children come from the `<Link>` in `render`). Fixed by forwarding `children: childRender ? undefined : children` into the `useRender` props, mirroring `SidebarMenuButton`. Any `useRender`-based primitive here must forward children the same way.

**Button compatibility aliases:** `default` maps to `primary` and `accent` maps to `tertiary` only so older integrations do not break during the migration. New call sites must use the six semantic variants above; remove aliases after the remaining external/generated integrations no longer reference them.

**Native controls & the single Select** (2026-07-15): the app now sets CSS `color-scheme` (`light` on `:root`, `dark` on `.dark`) so UA-rendered controls (dropdown popups, scrollbars) follow the theme — before this, native `<select>` popups rendered as white OS menus in dark mode. Every dropdown is the **one** design-system `Select` (`components/ui/select.tsx`, Base UI); raw `<select>` is retired. Migration notes: it works uncontrolled (`name` + `defaultValue`) or controlled (`value` + `onValueChange`, which yields `string | null` — coalesce), and posts in native `<form>`s via a hidden input; pass **`items`** (a `{value: label}` map) to the Root whenever the value ≠ its label (e.g. team id → name) so the trigger shows the label while the popup is closed. `""` is a valid item value (used for "Compartilhada"/"Não atribuído").

### 9.3 State patterns (required states, §3, now uniform)

- **Empty**: always `EmptyState` (or an affirmative panel) — never a bare table or "no data". Cold-start Home is a CTA hero listing what a budget + a source unlock; Explore/atribuição/roster/assinaturas/drill-down each have a contextual empty with the obvious next action; Admin-gated screens show a lock-icon `EmptyState` explaining "controle, não vigilância".
- **Role-gated settings**: `/ajustes/conexoes` and `/ajustes/assinaturas` gate the whole page behind `currentRole()` (`lib/auth/session.ts`) with the lock-icon `EmptyState`, since a connection/subscription form has no read-only meaning for a Viewer; `/ajustes/orcamentos` and `/ajustes/roster` instead render read-only (inputs `disabled`, admin actions hidden, submit replaced by the same explanatory line `CompanyForm`/`PrivacyForm` use) since budget and headcount are context a Viewer legitimately reads. The `/ajustes` hub reflects the same split — locked cards show "Restrito a administradores" instead of their usual count. `requireAdmin()` remains the sole authority on every mutation; the page-level gate never loosens it.
- **Loading**: per-route skeletons that mirror each screen's real shape and column width (RSC streaming, no client spinners, F1) — `app/(app)/loading.tsx` mirrors the Home cockpit's 2x2 grid; `times/loading.tsx`, `explorar/loading.tsx`, `ajustes/loading.tsx` (also covers the `/ajustes/*` subpages), `configuracoes/loading.tsx` and `times/[teamId]/loading.tsx` (header, executive summary, cumulative chart, mix/contributors, control plan — reuses `TableCardSkeleton`) mirror their own layouts, so no screen jumps between skeleton and content.
- **Error / data quality**: the global sidebar `StaleBanner` surfaces stale/failed syncs on every app route; page-level persistent notices are `Notice` (Σ-mismatch and FX-missing on Orçamentos, connection sync failure, unattributed spend on Times, locked currency); compact state chips are `StateBadge` (amber = data quality, destructive = failure); `ActionStatus` handles transient mutation results; the team-diagnosis calculation disclosures remain card-footer text ("as of" stamps, reconciliation lines).
- **Error boundaries & not-found**: four routes complete the layer — `app/global-error.tsx` (root layout itself failed; renders its own `<html>`/`<body>` and theme script, no sidebar), `app/(app)/error.tsx` (a route failed inside the shell; sidebar and nav survive, retry via `reset`), `app/not-found.tsx` (unmatched URL outside the shell; own wordmark + link home) and `app/(app)/not-found.tsx` (`notFound()` from inside the shell, e.g. an unknown team id; points back to Times). All four reuse `EmptyState`, pt-BR copy in local constants, neutral tone (no semaphore color), and never render a stack trace, exception message or digest.
- **All-clear**: affirmative soft-green notice (`AllClear`) in the sidebar footer, never a blank section — the screen's own affirmative answer is the green verdict line.
- **Settings hub**: `/ajustes` contains navigation Items only. Inline Company, Privacy, and Users sections move to `/ajustes/empresa`, `/ajustes/privacidade`, and `/ajustes/usuarios`.

### 9.5 Hydration & theme — QA-01 resolution (2026-07-11 audit)

Diagnosed per the audit plan: in a **clean browser** (no extensions), light and dark saved preferences, OS preference, first authenticated load, navigation and refresh all hydrate with **zero console errors**. The audit's mismatch (QA-01) reproduces only with the auditor's browser extension injecting `chrome-extension://…/youtube-hulu-vast-ads.js` into `<head>` — QA-01b confirmed; not a `themeScript` bug. The inline theme script stays as-is; `suppressHydrationWarning` on `<html>` (app/layout.tsx) is the narrowest justified boundary — it covers exactly the pre-paint `.dark` class the no-FOUC script adds — and no broader suppression was added. A DOM-level regression test would require a browser-test dependency the repo deliberately doesn't carry; the manual matrix above is the documented verification, and any future hydration error in a clean browser should be treated as a new bug, not as this known issue.
